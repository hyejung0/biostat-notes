Managing Your Notes

How to add, edit, remove, preview, and publish notes.

The files ending in .qmd inside notes/ are the source of truth. The website is generated from those files; do not edit anything inside _site/, because that folder is replaced every time the site is rendered.

Add a new note

  1. Choose the most appropriate subject folder inside notes/: Bayesian, Causal_Inference, Clinical_Trials, Measure_Theory, or Other.
  2. Create a lowercase, hyphenated file name such as notes/Causal_Inference/missing-data-estimands.qmd.
  3. Begin with the metadata template below, then write the note in Markdown beneath it.
  4. Save any note-specific images in a neighboring folder, such as missing-data-estimands_figures/.
  5. Preview the site and check the new note, topic listing, and search results.
---
title: "Missing Data and Estimands"
author: "Hyejung Lee"
date: 2026-08-22
description: >
  A one- or two-sentence summary that helps identify this note in listings.
categories:
  - causal-inference
  - missing-data
bibliography: ../../references/references.bib
csl: ../../references/csl/nature.csl
---

Use stable, descriptive categories. In this project, categories are the topic tags that power Browse by Topic. You do not need a separate tags field. Existing topics are shown on the topic page and are a good vocabulary to reuse; use the same spelling and hyphenation whenever possible.

When a note uses an R package

GitHub renders the website on a clean computer and installs the packages listed under Imports in the project-level DESCRIPTION file. A library(packageName) line loads a package but does not install it.

Whenever you use a new package in an R code chunk:

  1. Add its name under Imports in DESCRIPTION.
  2. Use library(packageName) or packageName::function() in the note.
  3. Install it on your computer if needed with install.packages("packageName").
  4. Render the current note while editing, then run the complete site once before pushing.

The rmarkdown package is required by Quarto’s R rendering process and must remain in DESCRIPTION. You do not need to add library(rmarkdown) to individual notes.

Edit an existing note

  1. Open the matching .qmd file under notes/.
  2. Change the text, code, equations, citations, title, description, or categories.
  3. If you rename the file, update links from other notes that point to the old file name.
  4. Preview the site before publishing.

The site-wide search index and all listings are rebuilt automatically. There is no separate database or manual search index to update.

Delete a note

  1. Delete the note’s .qmd source file.
  2. Delete its figure or attachment folder only if no other note uses those files.
  3. Search the project for links to the deleted file and remove or replace them.
  4. Render the site. The note disappears automatically from navigation, topic pages, the title index, and full-text search.

Render only the current note

For everyday editing, keep the .qmd file saved and active in the RStudio editor. Run this in the Console:

source("scripts/render_current.R")

That command detects the active editor file and renders only that document. It does not render all the other notes.

You can also provide a note path from the Terminal:

./scripts/render_note.sh notes/Bayesian/bcf.qmd

For a live preview that watches only one note:

./scripts/preview_note.sh notes/Bayesian/bcf.qmd

RStudio recognizes this as a website project, so its website-level Render/Preview action may initialize multiple pages. Use the commands above when you want guaranteed single-document rendering.

Preview or render the complete website

Use a full-site preview when checking navigation, topic filters, search, or shared styling:

quarto preview

For the final check before publishing, render the entire website:

quarto render

The finished local website is written to _site/. The project reuses results from unchanged computational notes during global renders, but direct single-note renders always execute the selected note.

Publish an update

The included GitHub Actions workflow publishes the site to GitHub Pages whenever you push to main or master.

git add .
git commit -m "Update biostatistics notes"
git push

On the first publication, create a GitHub repository, push this project to it, then choose Settings → Pages → Build and deployment → Source → GitHub Actions. The Actions tab shows the build. If the first run started before GitHub Pages was enabled, open that run and choose Re-run all jobs. When it finishes, Settings → Pages shows the public URL.

Before each publication

  • Confirm quarto render completes without an error.
  • Confirm every R package used by the changed note is listed in DESCRIPTION.
  • Open at least the changed note and check equations, figures, tables, and links.
  • Confirm the note appears under the correct subject and in All notes.
  • Search for one distinctive phrase from the note using the navigation-bar search.
  • Commit source files and attachments, but not _site/.

If GitHub reports there is no package called 'x', add x under Imports in DESCRIPTION, commit the change, and push again.

For a compact repository-oriented version of these instructions, see MAINTENANCE.md in the project root.
